What's Missing / Broken
1. Post-Training Visualizations — ALL PLACEHOLDER
src/pages/Visualizations.tsx — Confusion matrix, ROC curve, feature importance, residuals all show "Coming soon" with dashed placeholder boxes. No backend endpoints exist to compute these.
2. No Predictions / Inference
No endpoint or UI for using a trained model to predict on new data. The pipeline has train/test split, but models can't be used for real inference.
3. No Downloadable Reports
No report-generation endpoint (PDF, HTML summary, or JSON export of the full workflow).
4. EDA startEDA is undefined (bug)
EDA.tsx:16 destructures startEDA from useEDA(), but useEDA does not expose it — it only returns { status, report, isProcessing } (line 82). Calling startEDA as a callback will throw at runtime.
5. Training target column inference is buggy
backend/app/api/v1/endpoints/training.py:99:
target_col = [c for c in train_df.columns if c not in test_df.columns or True][-1]
The or True always evaluates to True, so it always picks the last column regardless of which target column was requested.
6. Pipeline execution is blocking
backend/app/api/v1/endpoints/pipelines.py:180 uses await loop.run_in_executor(...), blocking the request until the pipeline completes. This contradicts the background-thread pattern used by EDA.
7. Pipeline only supports CSV + Parquet
_run_pipeline_background only handles .csv and .parquet. JSON/XLSX uploads will silently fail with a bare return.
8. Duplicated chart components
BoxPlotSVG, StatCard, DataTable, MissingnessSection, etc. are duplicated across EDA.tsx and DatasetOverview.tsx.
9. useColumns hook calls wrong endpoint
useEDA.ts:89 calls getEDAStatus() instead of the dedicated GET /datasets/{id}/columns endpoint.
10. XGBoost dependency untracked
training.py imports xgboost but it's not in any requirements.txt or pinned dependency file.
